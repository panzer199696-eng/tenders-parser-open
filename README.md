# tenders-parser-open

Ночной сбор коммерческих закупок с открытых торговых площадок в одну
SQLite-базу: склейка дублей между площадками, отраслевой справочник тем
(классификатор «наше / не наше» с объяснением словами), честный отчёт о
полноте сбора, книга Excel и веб-окно на Flask.

Программа работает только с открытыми разделами площадок: без входа по
логину, без капчи и без передачи данных куда-либо, кроме самих площадок.

## Что умеет

**Площадки**

| Площадка | Как ищет | Браузер |
|---|---|---|
| ЕИС (zakupki.gov.ru) | RSS расширенного поиска по фразам; выключена по умолчанию | нет |
| Bidzaar (агрегатор) | JSON API: фразы + названия заказчиков | нет |
| ТЭК-Торг | JSON API: фразы + профильные секции с отбором по ИНН/названию | только запасной путь при антиботе |
| Росэлторг | HTML-выдача: адресно по ИНН заказчиков (+ фразы, выключены по умолчанию) | нет |
| Tender.pro | страницы выдачи по названиям заказчиков | да (Playwright) |
| ГПБ | по названиям заказчиков; выключена по умолчанию | да (Playwright) |

**Обработка**

- Единая база `data/tenderwork.db`: лоты, их публикации на разных площадках,
  реестр заявок, журнал прогонов.
- Склейка дублей: одна закупка с площадки и с агрегатора — один лот; «лицом»
  становится первоисточник (порядок — `src/platforms.py`).
- Профиль: группы номенклатуры с весами, заказчики с уровнем работы,
  профильные пороги цены → оценка лота и объяснение («Насосы +30 ·
  закреплённый клиент +40 · совпало „насос центробежный“»).
- Лента в окне по корзинам (Горит, Основной профиль, Закреплённые клиенты,
  Ниже порога, На проверку, Пропал, Срок истёк), реестр заявок, отчёты.
- Книга Excel после каждого прогона; диагностический zip (хвост журнала и
  настройки без секретов) сохраняется локально по кнопке.
- Расписание через Планировщик задач Windows и догоняющий прогон после
  неполной ночи.

## Запуск

Нужен Python 3.12 (проверено на Windows 11).

```bash
pip install -r requirements.txt
playwright install chromium     # нужен Tender.pro, ГПБ и запасному пути ТЭК-Торга
python main_ui.py               # окно: http://localhost:5000 (порт — переменная PORT)
python main_ui.py --collect     # один прогон сбора без окна (для планировщика)
python main_ui.py --collect --retry-incomplete   # догон площадок, упавших ночью
```

Коды выхода `--collect`: `0` — собрано полностью, `1` — ошибка или сбор уже
идёт, `2` — прогон дошёл до конца, но данные неполные.

Тесты (сеть в тестах запрещена на уровне сокета, см. `conftest.py`):

```bash
python -m pytest tests -q
```

## Где настраивать

При первом запуске программа копирует примеры из `defaults/` в папку данных
(в dev-запуске — корень проекта; переопределяется переменной
`TENDERSPARSER_DATA_DIR`). Все примеры вымышленные — замените их своими.

| Файл | Что в нём |
|---|---|
| `data/nomenclature.json` | **источник:** группы номенклатуры — фразы поиска, термины распознавания, вес, tier |
| `data/clients.json` | **источник:** заказчики — уровень работы, алиасы, ИНН |
| `data/rules.json` | профильные пороги цены по группам |
| `keywords.json` | фразы поиска (собирается из номенклатуры, ручные переключения сохраняются) |
| `companies.json` | заказчики для обхода по названию (собирается из `clients.json`) |
| `client_inns.json` | ИНН для обхода по ИНН (собирается из `clients.json`) |
| `settings.json` | площадки, пороги, расписание, заказчики «особого контроля» (`watch_clients`) |
| `.env` | необязательно: значения для первого запуска и `PROXY_SERVER` (см. `.env.example`) |

Справочники удобнее править в окне: вкладка «Справочники» сохраняет
источник и сразу пересобирает производные файлы.

## Справочник тем (классификатор)

Группа номенклатуры в `data/nomenclature.json`:

```json
{
  "id": "pumps",
  "title": "Насосы и насосное оборудование",
  "weight": 30,
  "enabled": true,
  "tier": "daily",
  "industry_sensitive": true,
  "match": {
    "strong": ["насос центробежный", "насосный агрегат"],
    "weak": ["насос"],
    "qualifiers": ["центробежный", "погружной", "ЗИП"],
    "exclude": ["пожаротушения"]
  },
  "phrases": ["Насос центробежный", "Насосный агрегат"]
}
```

- `strong` — однозначная позиция, даёт полный вес группы;
- `weak` — общее слово: само по себе даёт лишь долю веса и пометку «на
  проверку», рядом с `qualifiers` становится уверенным совпадением;
- `exclude` — вето для группы («насос для пожаротушения» — не наш насос);
- сравнение по словам с учётом падежей и порядка слов; короткие слова и
  марки с цифрами («НШ 1-15») сравниваются точно;
- `industry_sensitive` — вес режется, если заказчик из чужой отрасли
  (маркеры `industry.foreign`) и урезается, если отрасль неизвестна;
- `own_production: true` — бонус группе вашего собственного производства;
- `tier: daily` — фразы группы ищутся каждый день, а лоты попадают в
  корзину «Основной профиль»;
- `anti_groups` и `stop_words` — форма закупки (подряд, услуги) и явно
  чужие темы.

Перед сохранением из окна справочник проверяется
(`src/store/derive.validate_nomenclature`): дубли id, слишком короткие
`strong`-термины, один термин в `strong` двух групп, `weak` без `qualifiers`.

## Полнота сбора

Каждый парсер отчитывается по каждому объекту обхода (фраза, заказчик,
секция): сколько страниц/лотов обещала площадка и сколько собрано
(`src/parsers/completeness.py`). Причины неполноты называются словами:
упор в потолок страниц, обрыв связи, антибот, сменившийся формат ответа,
таймаут площадки. Общий сторож раннера помечает площадку, которая
промолчала или дала ноль лотов, а межпрогонная проверка
(`src/core/run_health.py`) — площадку, давшую в разы меньше обычного или с
застывшей лентой. Итог пишется в журнал прогонов, в окно и в книгу Excel
(блок «Полнота сбора по площадкам»): неполный сбор не выдаётся за полный.

## Устройство

```
main_ui.py              точка входа: Flask-окно и режимы --collect
src/core/               сбор (collect), раннер площадок, проверка связи, Excel
src/parsers/            парсеры площадок, полнота сбора, общие функции
src/db/                 схема единой базы, лоты, склейка дублей, лента, отчёты
src/profile/            оценка лота по справочникам
src/store/              справочники и производные файлы
src/registry/           реестр заявок
src/ui/                 маршруты, шаблон и статика окна
defaults/               примеры справочников и настроек для первого запуска
tests/                  офлайн-тесты (фикстуры ответов площадок обезличены)
```

## Ответственность

- Соблюдайте правила использования площадок и их ограничения на частоту
  запросов. Паузы между запросами в парсерах заложены намеренно — не
  уменьшайте их. На троттлинг (429/503) ТЭК-Торг отвечает паузой и повтором,
  остальные площадки при отказе честно помечают обход неполным.
- Форматы ответов площадок меняются без предупреждения: сторож формата
  сообщит о неполном сборе, но парсер может потребовать правки.
- Программа не подаёт заявки и не работает с электронной подписью — только
  собирает и упорядочивает открытую информацию.
- Код распространяется «как есть», без каких-либо гарантий (см. `LICENSE`).
